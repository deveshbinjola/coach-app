Book Research · Hooked (Nir Eyal) · Applied to Coach Assistant

The loop already half-built.

Eyal's Hook Model: Trigger → Action → Variable Reward → Investment, repeated until reaching for the product takes no thought at all. This isn't a generic application, it's mapped against the actual Coach Assistant codebase as it exists today. Two of the four phases are already real and working, coded by name in places. One phase has a hard, findable gap. One is thinner than it looks.

Book: Hooked, Nir Eyal, 2014 Grounded in: real routes + files, not speculation Date: 2026-07-30
THE FOUR PHASES, AS THEY ACTUALLY EXIST TODAY

What's built, what's missing.

1

Trigger

Weakest phase — real cliff found
What's working: a 5-day email drip (lib/email/onboarding-sequence.ts + app/api/cron/onboarding-drip/route.ts) fires Day 0 through Day 4, each subject line teasing the next email. /meet and /win are real top-of-funnel triggers, both emailing a personalized result. One genuine internal-trigger loop already exists: the "your voice has new material, re-tune?" banner on /content, computed by detectCorpusDelta in lib/brand-os/voice-overlay.ts, fires off accumulated investment data.
The gap: the drip stops cold after Day 4. There is no push notification, SMS, unread-count badge, or ongoing nudge anywhere in the codebase for a coach who has already activated. /today, the single most obvious page name for a daily-return trigger, is a dead stub that redirects straight to /command-center. Once the drip ends, the product has no mechanism left to reach out. Every return after day 5 depends entirely on the coach remembering to come back on their own.
2

Action

Real, and named correctly in the code
What's working: the Welcome flow (components/WelcomeFlow.tsx) has a step literally called "Magic" — paste a real lead message, tap a button, watch the AI draft a reply in the coach's own voice. The code comment calls this "the activation moment," which is exactly right in Fogg's Behavior Model terms: high motivation (a real stuck message), minimal ability required (paste and tap), trigger already present (the flow put it in front of them). This is the cleanest phase in the whole product.
3

Variable Reward

Good instinct, one accidental design flaw
What's working: The Mirror (/mirror, lib/mirror.ts) is a strong hunt/self reward, paste a stuck situation, get it classified and named with a "the mistake" / "the move" read. Code comment calls it "day-one sticky, the read lands on use #1." Command Center's Business Pulse (lib/ambient.ts, scoreRightNowItems) surfaces a genuinely changing hero item built from real data, a session coming up, a sequence that failed, a message waiting 48 hours.
The flaw: pickHonestQuestion(now) in lib/ambient.ts rotates through 14 hardcoded questions by day-of-year, deterministically. Eyal's whole point about variable reward is that unpredictability, not the reward itself, is what hooks. A rotation the user could eventually predict is not variable in the sense that matters, it's just a rerun schedule. This is the one place where the instinct was right and the implementation accidentally removed the exact mechanic it was going for.
4

Investment

The best-built phase, someone already understood this book
What's working: the voice profile/corpus (lib/voice-profiles.ts) compounds with every interview answer or imported writing sample, and directly loads the next Trigger phase (the retune banner). Mirror reads are logged to cp_mirror_reads and the PATCH handler in app/api/mirror/route.ts is explicitly commented "the investment step." Leads, sessions, and payments accumulate and directly sharpen the Business Pulse scoring over time. This phase was clearly built with the Hook Model already in mind, whether or not whoever wrote it had read the book.
SHIP THIS

Four moves, in order of leverage.

01

Build the post-Day-4 trigger. This is the single highest-leverage gap in the product.

app/api/cron/onboarding-drip/route.ts · app/today/page.tsx
The drip cliff is not a content problem, it's a missing state machine. Extend the cron past Day 4 into an ongoing weekly cadence keyed off Business Pulse data (a session coming up, a lead gone quiet, a sequence that failed) instead of a fixed script, since the ambient scoring already exists in lib/ambient.ts and just isn't being used to trigger anything. Separately, decide honestly whether /today should become a real daily-return surface or get removed as a route, a dead stub with the most Hook-Model-obvious name in the app is worse than no stub at all.
02

Fix the variable reward that isn't actually variable.

lib/ambient.ts (pickHonestQuestion)
Swap the deterministic day-of-year rotation for a weighted-random pick from the same 14-question pool, excluding whatever was shown in the last N visits. Small change, and it closes the one real gap between what this feature was clearly trying to be and what it currently is.
03

Decide, in writing, whether the disabled progressive-reveal system comes back.

lib/nav-unlocks.ts
This file shows a progressive nav-unlock mechanic was built, then deliberately turned off ("Full nav for everyone, no progressive reveal"). That's a real Investment-phase lever sitting dormant, unlocking more of the product as a coach's own data (leads, sessions, voice samples) grows is a clean way to make the app feel like it's becoming more theirs over time. Worth one explicit decision: was it disabled because it tested badly, or because nobody finished wiring it. Different fixes follow from each answer.
04

Run every new mechanic through Eyal's own two-question test before it ships, not after.

n/a — process, not code
Does it materially improve the coach's business. Would Sunny use it himself, running a coaching business, without knowing he wrote it. This matters more here than in most products, because the whole brand promise (presence over compulsion, regulate the nervous system) is the opposite of what a badly-tuned streak or slot-machine mechanic communicates. The book's own ethics chapter is the sharpest available check against accidentally building the thing Sunny's actual coaching work exists to undo.
The guardrail, stated plainly

Eyal wrote a follow-up book, Indistractable, partly in response to the backlash that Hooked was a manual for building compulsive products. His own Manipulation Matrix (Facilitator, Entertainer, Peddler, Dealer) is graded by the person with the least incentive to fail it, the founder. That's not a reason to ignore the model, the mechanics are real and mostly already half-built here correctly. It's a reason to keep the two-question test written into whatever process gates new features, not left as a book read once. Revenue-outcome-per-coach is the number that matters. Daily-active-use and streak count are not the number.
